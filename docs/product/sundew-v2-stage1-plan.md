# Sundew V2 — Stage 1 开发计划

状态：已在工作区实现；空数据账户、桌面与移动视口已验收，有真实历史数据的最终人工验收待实际账户使用时补充。
日期：2026-09-15
上级计划：[Sundew V2](sundew-v2-plan.md)

## 1. 交付目标

让用户打开首页就知道今天可以做什么，能够立即开始，也能自由选择其他练习。

Stage 1 完成时应满足四件事：新用户能开始，老用户能继续，推荐理由能追溯到记录，完成状态与实际任务一致。

本计划细化并调整 V2 总计划的 Stage 1 首页层级。实施顺序为：

1. 导航与目标设置。
2. Today 主任务与四技能入口。
3. 近期证据、本周摘要和整体验收。

本阶段不包含新口语对话、TCF 写作、Agent、通用学习信号平台、题库扩充或生产部署。已有付费功能仍遵守现有权限和预算边界；打开首页、加载导航和计算推荐不调用模型。

## 3. 页面与导航约定

### 3.1 Today 信息层级

```text
Today                                      Edit goal
General French / TCF preparation · 可选考试日期

┌─────────────────────────────────────────────────┐
│ 今日推荐：一项具体活动                             │
│ 推荐理由 · 预计用时（估计）                        │
│ [Start / Continue]           Choose another      │
└─────────────────────────────────────────────────┘

Listening       Speaking       Reading       Writing

Recent focus areas
最多三条：具体观察 → 来源记录 → 可用后续活动

This week                                  View progress
真实活动数量；明确各自单位
```

- 目标是一行上下文，今日推荐是唯一强视觉区域。
- TCF 用户的目标区域显示考试入口、可选 CLB 和日期；不再增加重复的大型 TCF 模块。
- 普通学习用户始终能从导航进入 TCF，但首页不要求填写 CLB。
- 四技能始终可见；每项显示可用练习模式，以及有可靠来源时的最近活动。
- 缺少某技能的追踪数据时显示“尚无可用记录”，不能推断用户没有练过。
- 无错误证据时用一条简短引导代替三张空卡；无本周记录时提供首次练习入口。
- 新增界面文案使用英文，练习内容使用法文。既有练习页面的全面语言统一不在范围内。
- 复用 Sundew 字体、语义颜色、logo 和共享组件；不引入另一套视觉主题。

### 3.2 桌面与移动导航

| 分组 | 入口 | 目标路由 |
| --- | --- | --- |
| 日常学习 | Today / Training / Review | `/today` / `/training` / `/review` |
| 考试准备 | TCF Canada | `/tcf` |
| 资料与记录 | Library / Progress | `/library` / `/progress` |
| 账户 | Settings | `/settings` |

移动端底栏固定为 Today / Training / Review / More。More 包含 TCF Canada、Library、Progress、Settings；备考用户另有 Today 的直达入口。

新增 `/training` 与 `/review` 放在 `(main)` 布局中。现有路径、查询参数和记录保持有效。Logo 与 TCF 返回主应用的链接改为 `/today`。

导航高亮使用明确的归属映射：`/practice`、`/speaking`、`/quiz`、`/conjugation` 属于 Training；`/vocabulary` 及子路径属于 Review；文档阅读属于 Library。最长/最具体的匹配优先，避免两个入口同时高亮。TCF 继续使用自身导航。

### 3.3 聚合页的范围

| 聚合入口 | 复用目标 | 呈现约束 |
| --- | --- | --- |
| Training → Listening | 现有 TCF 听力入口；已验证可用的听力类练习 | 明示 TCF 模式，不包装成新的通用听力课程 |
| Training → Speaking | `/speaking` | 标明现有脚本/发音练习；交互模拟尚未上线 |
| Training → Reading | `/library`、TCF 阅读入口 | 区分个人材料阅读与考试练习 |
| Training → Writing | `/practice`、现有 Quick Write | 明示一般写作，不标为 TCF 写作 |
| Training → Supporting practice | `/quiz`、`/conjugation` | 保留可发现性，避免增加顶层导航 |
| Review → Vocabulary | `/vocabulary/review`、`/vocabulary` | 分别标明到期复习和已保存词 |
| Review → TCF review | `/tcf/review` | 使用目标页支持的真实过滤条件 |
| Review → Writing errors | `/progress` 的既有分类筛选、具体反馈页 | 标明查看错误；只有已有对应练习时才写“练习” |

聚合页只负责组织入口和摘要，不复制练习引擎、评估流程或历史数据。没有内容或服务配置的模式说明原因，并给出可行替代入口，不使用不可用的主按钮。

## 4. 最小数据约定

### 4.1 学习目标与兼容

继续使用 owner-scoped `userSettings`，新增：

- `learning_mode`：`general` 或 `tcf`。
- `time_zone`：经服务端验证的 IANA 时区。

保留 `target_clb`、`exam_date`、`cefr_level`。CEFR 是自报难度基线；未设置时可选择默认入门难度，但页面不得称其为测得水平。

兼容规则：已有有效 CLB 或考试日期且没有 `learning_mode` 时，读取为 TCF；否则读取为 general。读取兼容不触发全表回填；用户下次保存时持久化方向。切换方向不清除原考试字段，清空字段必须是显式编辑。

服务端验证方向枚举、CLB 范围、真实日历日期和时区。目标写入在事务内完成，不信任客户端 owner。普通用户无需管理员权限即可读取和修改自己的目标。

目标保存后刷新 Today、Settings、Progress，以及消费目标的聚合页。个人目标编辑不能依赖 API key 检测成功，也不应触发该检测。管理员诊断保留为独立、显式操作。

### 4.2 日期与统计

- 首次可从浏览器检测时区并通过显式设置保存；允许手动修改。
- 尚未设置时使用明确标注的 UTC 回退，不从部署服务器本地时区推断用户日期。
- Today 使用用户时区的自然日；This week 定义为周一 00:00 至当前时刻，并显示日期范围。
- 数据库时间戳继续使用现有格式；查询将用户本地边界转换为 UTC，包括夏令时。
- 考试日期是当地日历日期：当天显示 Today，已过期显示日期已过并提供编辑入口，不能显示负数倒计时。

### 4.3 页面数据与推荐状态

新增轻量的 Today 领域类型，包含目标、活动候选、推荐理由、来源引用、完成条件、可用性、最近活动和本周摘要。规则模块使用这些类型，不直接依赖 React 或数据库。

为保证返回首页后不会自动追加任务，持久化用户主动开始/选择的当日活动：

- 使用用户设置中的一个版本化 `today_focus` JSON 值，只保留当前选择，不建立第二套练习历史。
- 保存本地日期、时区、活动类型、合法目标 ID/筛选条件、选择时间及用于计算完成的范围。
- 仅在用户开始或显式更换时写入；页面读取不创建任务、调用模型或写入选择。
- 服务端重新验证候选、归属与目标可用性；不接受任意跳转地址或客户端提供的完成状态。
- 完成状态从原始练习记录计算。更换活动不删除历史；新一天重置选择，已失效的目标提供重新选择入口。
- 重复点击不得覆盖进行中的选择或重复创建练习；复用原流程已有的去重机制，缺少时在该入口补最小保护。

这是 Today 的最小状态，不替代 Stage 3 的共享学习信号规范。若实现中发现键值存储无法满足并发一致性，再记录依据后改用小型专用表，不预先建设通用推荐平台。

## 5. 推荐与完成规则

### 5.1 选择顺序

1. 已选当日活动：展示原活动的继续、进度或完成结果；不自动换题。
2. 未选择时，有已验证可恢复的活动：推荐继续。必须实测对应页面能恢复；有 `active` 字段不等于可恢复。
3. 有到期复习，或近期错误且存在对应练习：推荐一项范围明确的复习。
4. 按学习方向选择可用活动：TCF 优先适合目标的考试练习，general 优先普通学习入口。
5. 证据不足：提供明确的首次练习。无材料、无配置时回退到内容选择/导入入口，并诚实标为设置步骤。

同级候选按最近活动时间和稳定 ID 排序；相同输入应得到相同结果。TCF 正确率可作为相同技能/等级内的练习观察，但不跨难度直接宣称“最弱技能”。

`Choose another` 展示可用候选；每次只选一个。活动预计时间使用明确标注的静态估计，不能写成已测量的个人耗时。

### 5.2 完成判定

| 活动 | 完成依据 |
| --- | --- |
| 指定 TCF 技能/等级的 N 题 | 所选范围内已持久化的 N 道不同题目；限定 drill 模式和本次选择范围，其他技能/等级/考试记录不能凑数 |
| 写作任务 | 对应 task 的 submission 已保存；反馈 pending/failed 与提交完成分别显示 |
| 变位 N 题 | 所选范围内 N 条有效作答，不能一题即完成；重复请求不得多计 |
| 词汇复习 | 选择时记录的有限到期卡集合均有此后复习记录；不能以收藏总数或当前队列减少量代替完成 |
| 阅读/口语等其他模式 | 只有现有数据足以验证完成时才显示完成目标；否则作为自由练习入口，仅显示最近活动 |

实施时先核对每种模式能提供的记录。无法可靠关联的模式继续保留在四技能/聚合页，但不作为带数值完成承诺的主任务。不得为凑齐模式虚构 session 或 completion。

已完成时显示完成结果和可选的 `Choose another`，不自动换成下一个任务。服务端同步尚未完成的 TCF 作答不得提前显示为已保存；返回 Today 后提供最新数据刷新。

## 6. 近期证据与本周摘要

### Recent focus areas

- 初版仅使用有来源的写作错误，限定最近 30 个用户自然日，最多三项。
- 同一问题在至少两次不同 submission 中出现，才可称为 repeated；同一次写作的多个错误不能算多次练习。
- 一次出现时只描述“一次记录中的观察”，不称为弱项或退步。
- 每项包含类别、出现的独立练习次数、最近日期、原反馈链接以及可用后续入口。
- 已删除、无权访问或缺少来源的证据不参与个性化判断。
- 后续入口只支持查看错误时，就写查看错误；已有微练习/对应生成动作时才写练习，并标明需主动开始。

### This week

初版优先展示可核实的单位：TCF 作答题次、提交写作篇数、变位作答题次；口语和阅读仅在记录语义确认后加入。不同单位分开显示，不累加成“完成 X 次学习”。

不展示学习分钟数、能力提升百分比或“已掌握”，除非有足够来源和明确计算口径。某来源查询失败时标记暂不可用，不显示 0。活动摘要不足不阻塞四技能入口。

## 8. 验证计划

### 必须覆盖的行为

| 场景 | 预期 |
| --- | --- |
| 新用户、无历史、无考试目标 | general 首页可用；提供实际可开始的活动或必要设置入口 |
| 只有 CLB / 只有考试日期的旧用户 | 正确兼容到 TCF；不丢失字段 |
| general 与 TCF 来回切换 | 目标与历史保留，首页上下文刷新 |
| member 打开 Settings | 可编辑个人目标，不执行管理员检测 |
| 用户 A/B 访问同一活动 ID | 仅 owner 可获取私人数据和保存选择 |
| 同一错误只在一篇写作中出现多次 | 不宣称反复发生于多次练习 |
| 主任务为听力，用户完成阅读 | 不误计为该听力任务完成 |
| 变位完成 1/10、10/10 | 分别显示进行中和完成 |
| 写作已提交，反馈生成失败 | 提交完成与反馈失败分别呈现 |
| 有收藏词但无到期 gap | 不显示虚假的待复习数量 |
| 完成主任务后刷新或重新登录 | 同一天仍显示该任务的完成结果 |
| 重复点击、两标签页、来源删除 | 不重复创建任务；无越权；可从失效状态恢复 |
| 当地午夜、周一、夏令时切换、考试当天/已过期 | 日期边界与标签正确 |
| 部分数据源失败、模型服务未配置 | 首页入口可用，缺失数据不伪装为零或成功 |

为推荐规则、完成范围、日期边界、兼容解析和所有权写入添加有意义的定向测试；不为纯展示组件或样式变更编写镜像测试。恢复能力、跨页面返回和真实数据权限使用本地集成/浏览器验证，不能只以 mock 测试代替。

### 命令与视觉检查

- 运行修改涉及的测试：`npx tsx --test <相关测试文件>`。
- 运行 `npm run typecheck` 与 `npm run lint`。
- 合并本阶段各批次后运行 `npm run test` 和 `npm run build`；已通过后仅在新改动/失败需要时重跑。
- 检查 390px 手机和 1280px 桌面；补查 320px 无横向溢出、200% 缩放、键盘导航、焦点返回和底栏安全区。
