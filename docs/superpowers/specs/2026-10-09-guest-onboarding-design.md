# Guest Onboarding — Design Spec

> The first minutes of a guest account (the recruiter path: landing →
> "Try the full app" → app). Fixes six observed problems by presentation and
> routing only; guest permissions are unchanged.
>
> Designed in a brainstorming session on 2026-10-09 from a code walk-through of
> the guest path. Facts verified on 2026-10-09. Stacked on
> `feat/sitewide-glow-theme`.

---

## 1. Problems (observed in code)

| # | Problem |
|---|---|
| 1 | The locked TCF page links "Try an original sample question" to `/#try-demo`, but `/` redirects every signed-in user — guests included — to `/today`. Broken since the landing redesign. |
| 2 | No orientation: a guest lands on Today with no word that the data is sample data, where to look, or what is locked. |
| 3 | The strongest demo (classified writing feedback) is buried: on Practice a disabled quick-write button leads, sample feedback is a small text list. |
| 4 | The locked page is an invite-code form; it never says why a feature is locked or what to try instead. |
| 5 | Locks everywhere (sidebar TCF, two of four Today skill cards, Training cards) read as "half of this is broken". |
| 6 | A guest cannot get back to the landing page or the source code from inside the app. |

Already right: Today's focus filters TCF activities out for guests.

## 2. Decisions

| # | Decision |
|---|---|
| D1 | `/` shows the landing page to signed-out visitors **and guests**; full members and admins still go to `/today`. Fixes #1 and gives #6 a destination. |
| D2 | On the landing page a guest sees **Continue the demo** (→ `/today`) instead of "Try the full app", without the "No sign-up…" caption; the header keeps a "Sign in" text link. |
| D3 | A guest bar on every `(main)` page: "**Sample workspace** — explore freely. This demo account is deleted on {date}. · Homepage · Source ↗". |
| D4 | A guest-only **Start here** card at the top of Today with three links: sample writing feedback, Progress, Conjugation. |
| D5 | Practice for guests leads with sample feedback cards; quick write moves below with a reason. |
| D6 | Locked pages become **preview pages** (what it does, why it is not in the guest tour, try instead, collapsed invite form). Locks become a "Preview" badge; inline "Invite only — have a code?" becomes "Members only — {reason}". |
| D7 | TCF reason stays vague: "Exam content is available to members only." |

## 3. Copy

**Reasons** (one per feature, stored as `memberReason` in `FEATURES`, `src/lib/access/features.ts`):

| Feature | Reason |
|---|---|
| tcf | Exam content is available to members only. |
| speaking | Every recording is scored by a paid speech service, and recordings are personal data. |
| quiz | Imports run your own files through paid AI. |
| writing | Feedback calls paid AI. |
| microDrill | Drills are generated by paid AI. |
| enrich | Full entries are generated by paid AI. |
| lookup | Look-ups outside the sample texts call paid AI. |
| upload | The guest tour uses the sample texts. |

**Preview pages** (the three page-gated features):

| Feature | What it does | Try instead |
|---|---|---|
| tcf | 3,000+ listening and reading questions by CEFR level · Drill and timed-exam modes, with an explanation for every question · Wrong or unsure answers flow into a review center | The original sample question → `/#try-demo` |
| speaking | Read-aloud practice scored by Azure Speech · A timed TCF Task 2 simulation | AI writing feedback → first sample submission (fallback `/practice`) |
| quiz | Import exam PDFs or podcasts; AI structures them into questions · Podcast cloze dictation · Auto-grading with attempt history | Conjugation drill → `/conjugation` |

**Start here card:** "Welcome — you're in a sample workspace" / "It's set up as an A2 learner. Three places show the learning loop best:" ① See AI writing feedback — a sample answer with every error classified ② Find the weak spots — how errors roll up into a learner profile ③ Try a conjugation drill — live, auto-graded practice. Footer: "TCF, speaking and quiz are previews: real exam content and paid AI stay with members."

## 4. Scope

**In:** `/` routing for guests; landing CTA/header for guests; guest bar; Start here card; Practice guest layout; preview page; Preview badges; members-only notes; moving `InviteDisclosure` to `src/components/`; a shared `SOURCE_URL` in `src/lib/site.ts`.
**Out:** what guests may use; sample workspace content; Today recommendation logic; anything a full member sees except the unchanged `/` redirect.

## 5. Verification

- Unit tests: landing CTA choice per viewer; every feature has a non-empty `memberReason`.
- `npm run typecheck`, `npm run lint`, `npm test`.
- Signed in as the owner: Today, Practice, Training, sidebar, `/tcf` show no guest UI and are unchanged; `/` still redirects to `/today`.
- Guest walkthrough needs a real guest account, which writes to the production database (auto-deleted after 7 days, counts toward the daily guest cap). Only with the user's consent: sign out in the browser pane, start a guest from the landing page, walk §1's six problems, screenshot each fix.
