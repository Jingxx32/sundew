# 邀请制用户、公开演示与上线安全实施计划

日期：2026-09-07。状态：实施中；2026-09-08 已完成第一批认证边界，数据库归属迁移尚未执行。

目标：招聘者无需登录即可体验产品；本人登录使用真实数据；后续少量受邀考友拥有独立学习空间。公开访客不触发付费 AI 调用。

## 1. 已确定的范围与待决策项

### 本轮方案

- 保留公开演示，同时建立轻量用户管理。首发仅启用本人账号，邀请入口第二阶段开放。
- 公共题库与知识共享；文章、作文、错题、词汇学习状态、设置、录音按用户隔离。
- 访客真实做题，进度仅保存在浏览器；AI 结果明确标为预先生成的示例。
- 所有私人数据读写及付费调用在服务端校验身份、账号状态和权限。
- 暂不做自由注册、支付、订阅、组织、排行榜和社交功能。
- 本文只授权和记录实施方案，不表示认证服务采购、云资源创建、数据迁移或上线已经完成。

### 建议默认值，实施时可调整

- 受邀用户使用站点提供的有限免费 AI 额度，不保存用户自己的 API Key；此项沿用讨论中的建议，尚非用户单独确认的费用承诺。
- 使用成熟身份认证方案，优先验证邮箱登录体验，不自行实现密码存储与找回。
- 初期使用现有 PostgreSQL 保存配额与调用账本；不因少量用户默认新增 Redis。
- 保留原 Azure 计划的双部署隔离：公开 demo 不连接私人数据库、无付费凭据；私有实例以后承载受邀用户。
- 产品入口统一：首页提供“体验演示”和“登录学习”，登录可跳转至私有实例。逻辑权限不依赖必须合并成单实例。

## 4. 身份模型与服务端边界

新增应用 `users`：`id`、`authIssuer`、`authSubject`、已验证邮箱、`role(admin/member)`、`status(active/disabled)`、创建/更新时间。`(authIssuer, authSubject)` 唯一；邮箱用于邀请匹配，不充当永久身份主键。

新增服务端模块（路径为计划新增，不代表已存在）：

- `src/lib/auth/session.ts`：验证会话，映射应用用户；`requireUser()` 返回内部用户 ID，且检查 active 状态。
- `src/lib/auth/permissions.ts`：`requireAdmin()` 及具名能力检查；默认拒绝未知能力。
- `src/lib/access/`：封装带所有者条件的数据访问；普通服务端模块使用 `server-only`，不标为 `use server`。
- `src/lib/demo/`：只读演示数据与演示 DTO，不调用真实业务 Action。
- `src/lib/validation/`：按操作提供运行时输入 schema，不能只依赖 TypeScript 类型。

实施约束：

1. 按安装版本阅读 `node_modules/next/dist/docs/01-app/02-guides/authentication.md`、`data-security.md` 及实际涉及的 Route Handler、缓存、部署文档。
2. 页面/layout 的跳转只负责体验；每个暴露的 Action、Route Handler 和私人读取入口都校验身份。不能只保护 `/api/*` 而漏掉 Server Actions。
3. userId 从已验证会话取得，忽略或拒绝客户端提交的所有者字段。更新/删除的 SQL 同时限制资源 ID 与 userId，不能只在前端校验。
4. 子资源通过同用户父资源关联；不存在和不属于本人对普通用户使用一致的 not-found 响应。创建时校验外键指向可用的个人/公共资源。
5. `after()` 工作在入口完成身份与额度校验后，显式携带可信 userId、operationId；执行付费步骤前再次检查状态和额度，不依赖后台重新读取请求 cookie。
6. 私人内容不进入跨用户共享缓存；聚合、预加载、导出、错误响应和缓存 key 同样检查用户范围。私人响应使用适当的 private/no-store 策略。
7. 若采用外层代理身份头，必须证明源站不能绕过代理、用户不能伪造身份头。不能直接相信客户端的邮箱头或 `x-forwarded-for`。
8. Cookie 使用 Secure、HttpOnly 和适当 SameSite；变更型 Route Handler 增加来源/CSRF 防护；登录回调和重定向白名单由认证方案处理。CORS 不代替鉴权。

## 5. 数据表与迁移设计

主要修改位置：`src/lib/db/schema.ts`、`drizzle/`、`src/lib/actions/`、`src/lib/vocabulary/` 和数据初始化脚本。

### 5.1 数据归属

| 当前表（schema 导出名） | 改造 |
|---|---|
| `documents`, `readingSessions`, `writingTasks`, `submissions`, `errors`, `microDrills` | 增加非空 userId；各链条父子归属一致，删除文章后保留的历史仍保有所有者 |
| `quizSets`, `quizPassages`, `quizQuestions` | 当前导入题集按个人内容处理；set 加 userId，子表经 set 归属校验；跨 set 的 passage/question 关联也需一致 |
| `quizAttempts`, `conjugationAttempts`, `tcfAttempts`, `tcfQuestionAttempts` | 增加 userId；成绩、复习队列和清空历史按用户过滤 |
| `speakingScripts`, `speakingSessions`, `speakingTurns` | 增加 userId；脚本 profileSnapshot 和转录都是私人数据，turn 与 session 归属一致 |
| `userSettings` | 主键从 key 改为 `(userId, key)`，全部 upsert 冲突目标同步修改 |
| `vocabularyOccurrences`, `vocabularyGaps` | 增加 userId，所有查询、计数和 upsert 按用户 |
| `tcfSets`, `tcfQuestions`, `speakingPrompts`, `rules`, `grammarPoints` | 保留公共知识属性，只允许受控维护；公共不等于允许匿名读取完整内容 |
| `vocabularyLookups`, `vocabularyAliases` | 按下一节拆分通用词典与个人学习状态 |

新增私有表的 userId 外键与常用 `(userId, createdAt)` / `(userId, status, dueAt)` 索引。对于同时存 userId 的父子表，使用父表 `(userId, id)` 唯一约束及对应复合外键，或经过审查的等价数据库约束，防止混合归属。删除策略逐表核对，不能对所有表一律 cascade。

### 5.2 词汇必须拆分，不能只给现表加一列

当前 `vocabularyLookups` 以 lemma 全局唯一，同时保存 `savedAt`、`lookedUpAt`、`sentenceContext`、`inContext` 和释义。`upsertEntry()` 会刷新上下文相关字段；直接共享会暴露或覆盖用户内容。

- 保留全局词典实体和 aliases：仅放独立于私人上下文的词性、通用释义、变位和通用 richEntry。动态公共词条由受控服务生成，普通用户不能提交内容覆盖全局词条。
- 新增 `userVocabulary`，唯一 `(userId, lemma)`，保存个人收藏、查词时间与个人展示字段。
- 上下文原文和针对上下文的解释保存在个人 occurrence/上下文结果表；缓存 key 包含 userId 与上下文摘要，不跨用户共享。
- 现有 `inContext`、`sentenceContext`、可能从私人语境生成的 translation/examples 等先归入本人私有记录。未确认可共享的 richEntry 不直接公开，可在后续用无私人上下文输入重新生成通用词条。
- `vocabularyOccurrences` 原去重约束加 userId，并保留原有 null 语义；`vocabularyGaps` 唯一约束改为 `(userId, lemma, gapType)`。
- 修改 `helpers.ts`、`gaps.ts` 和所有冲突更新目标。同一 lemma 可由两位用户分别收藏、复习，互不改变 box、状态和时间。

### 5.3 迁移顺序与恢复

1. 在隔离测试库上演练；记录各表行数、外键、唯一约束和关键个人统计。备份数据库与录音，验证备份可恢复。
2. 首次正式切换进入维护状态，停写并等待后台任务结束；不要让单用户旧代码与多用户新写入并行运行。
3. 创建 users 和本人的身份映射；增加暂可空的 userId、新词汇表、用量表。迁移脚本要求显式目标库及本人 ID，不默认回填到“第一个用户”。
4. 所有现存私人记录回填本人；孤立记录也明确归属，不以缺少父记录为由公开或直接删除。迁移收藏、上下文和设置。
5. 验证无遗漏、父子归属一致、收藏和统计数量相符，再替换唯一约束、加非空/外键/索引。未通过时停止发布。
6. 部署兼容新 schema 的应用，验证本人数据及双用户隔离后恢复服务。旧字段暂留至恢复窗口结束，再独立清理。
7. 回滚不能直接运行会忽略 userId 的旧版本。保持访问关闭，使用兼容版本修复；必须恢复备份时先保存故障后的新数据并评估损失。记录独立的数据库与媒体恢复点。

## 7. AI 额度、并发与请求安全

### 调用账本

新增 `aiOperations`（用户操作）与 `aiCalls`（实际服务商请求），以及原子更新的预算 bucket/策略表。

- operation 记录 userId、功能、幂等 key、输入摘要、状态、结果引用；唯一 `(userId, feature, idempotencyKey)`。相同 key 配不同输入应拒绝。
- call 记录 operationId、服务商/模型、状态、预留金额、实际/估计使用量、provider request ID 和时间；不记录原文或密钥。
- bucket 分别管理用户功能日额度、短时频率、并发数及全站累计预算；日界线统一 UTC，累计总预算不在午夜或重启后重置。
- 一次用户操作只扣一次操作次数，但内部每次付费请求单独入账。缓存命中不产生实际调用费用。
- 在短事务内按固定顺序锁定预算行，检查并预留所有额度，提交后再发外部请求，禁止数据库事务跨模型网络等待。
- 按经核验价格和受限输入/输出/音频长度预留成本。未知模型价格时拒绝调用，不使用零价格默认值；管理员也不能绕过累计预算。
- 成功后结算。超时但可能已计费的调用保留预留并标记待核对；不能立即退款再无限重试。过期任务的并发租约可恢复，成本预留不能因租约过期自动释放。
- 配置 SDK 重试：关闭隐式重试或将每次重试纳入最坏成本预留；失败重试次数受限。
- 多实例共用持久化账本；不可用时拒绝新付费调用，浏览和保存草稿仍可用。全站关闭开关阻止后续调用，不承诺撤回已发请求。
- 账本只覆盖本应用经过闸门的调用，不保证其他使用相同凭据的程序费用或云账单。服务商告警作为辅助，不能替代应用限额。

### 输入和资源限制

新增统一策略配置，具体数值在 S4 结合现有功能测试后填写，生产配置缺少必要上限时不启用对应付费功能。

- 文本长度、数组数量、输出 token、PDF 大小/页数/解析时间、音频大小/时长、参考文本长度都要有服务端上限。
- 入口/反向代理拒绝过大请求，应用流式读取也按累计字节中止；不能只信 Content-Length，也不能只在 `formData()`/`arrayBuffer()` 全部读完后检查。
- 音频验证实际格式、采样参数与时长，不只看 MIME/扩展名。客户端 orderIndex 仅接受有限范围整数；存储对象 ID 由服务端生成，重复序号不得覆盖别人的文件或重复计费。
- PDF/远程音频解析设置超时及资源边界；远程 URL 导入首发关闭。以后启用时限制 HTTPS 和明确来源，逐跳检查重定向与解析地址，阻止内网、回环、链路本地和元数据地址，并处理 DNS 重绑定及下载字节上限。
- 用户限流为主，可信代理 IP 限流为辅；同出口不应误判为同账号，可重建 cookie 不能充当可靠防刷身份。
- API 返回 401/403/404/413/429 等适当状态；限流带 Retry-After。Action 返回结构化错误和可恢复界面；详情仅进脱敏日志。

## 10. 验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 匿名直接调用付费 API / Action | 拒绝，mock 服务商调用计数为 0 |
| 匿名访问私人页面/已有录音 URL | 无私人内容；登录跳转或适当拒绝响应 |
| A 请求 B 的文章、作文、错误、script、session、录音 | 无内容泄漏、无写入、无付费调用 |
| A 创建记录时传 B 的父 ID / 伪造 userId | 拒绝，不留下跨用户外键关联 |
| A 重置 TCF 历史或复习同一 lemma | B 的成绩、gap、收藏、设置保持不变 |
| 两用户访问相同页面、画像、统计、缓存 | 各自只见本人数据，包括 join/子查询和空状态 |
| 停用用户保留旧 cookie 后继续请求 | 下一请求拒绝；不能兑换邀请恢复自身权限 |
| 伪造身份头 / Origin / 客户端管理员字段 | 不获得身份、权限或 CSRF 绕过 |
| 多实例并发争抢最后一份预算 | 仅允许可预留范围的调用，无超额、无负数 |
| 重复提交、换 key、模型超时、SDK 重试 | 同 key 不重复执行；换 key 仍受限额；不误退不确定费用 |
| 账本不可用、进程重启、午夜、全站关闭 | 新付费请求按策略拒绝；累计预算不重置；可继续浏览 |
| 超大分块请求、伪造长度、异常 PDF/WAV、外部 URL | 受控拒绝，不先完整缓冲无限输入或访问内网 |
| demo 没有 AI 凭据和私人 DB 访问权 | 演示仍完整可用；没有真实私人内容及付费请求 |
| 刷新/重置 demo | 仅影响该浏览器，其他访客与本人数据不变 |
| 新录音、重建容器、旧公开链接 | 新录音授权可播，重建后保留，旧公开路径不可读 |
| 数据迁移及恢复演练 | 行数/归属/收藏/统计核对通过，可恢复数据库及录音 |

代码验证：`npm run typecheck`、`npm run lint`、`npm test`；生产构建与隔离环境 smoke test。安全测试应调用真实 Action/HTTP 边界并连接隔离数据库，不能仅测 mock 的 requireUser。构建时不读取真实私人数据或调用模型。

交付记录每阶段填写：变更文件、迁移版本、命令、实际结果、未完成项、恢复点。使用 mock 通过不等于真实服务集成通过；真实调用只在服务启用和预算明确后进行。
